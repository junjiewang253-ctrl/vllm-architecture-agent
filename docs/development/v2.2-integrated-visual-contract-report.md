# v2.2 Integrated Visual Contract 开发报告

## 1. 背景

v2.1.x 已经完成 Agent-native 源码索引、完整审阅、Evidence、Draw.io MCP
绘图和结构验证，但较弱的 Agent 仍可能把 Plan 直接翻译成概念卡片。常见问题是：

- 主流程被拉成很长、很细的一条线；
- detail region 存在，但内部没有足够结构；
- branch/merge 只是文字标签，不是真正拓扑；
- multimodal、MoE 或 loading 被压成摘要节点；
- 第一稿 PNG 只做很小的移动便被视为完成；
- Evidence 的 `symbol` 不精确仍只产生 warning。

v2.2 不恢复旧 IR/Concept/View/Renderer 流水线，而是在 Agent 自主设计和
Draw.io MCP 绘图之间增加可验证的 Visual Contract。

## 2. 设计原则

职责保持不变：

- 脚本发现源码结构、校验证据和成品；
- Codex 决定架构语义、页面组织和布局；
- Draw.io MCP 创建、修改和导出最终图；
- 生产代码不包含模型专用页面、节点或坐标。

完整模型默认使用一张 `integrated_single_canvas`。只有两轮真实 MCP 修订后
仍不可读，才允许改成少量 `composite_pages`。

## 3. Architecture Plan 2.2

Plan 2.2 增加：

- `diagram_strategy`；
- `integration_rationale`；
- detail region `integration`；
- page `visual_contract`。

`visual_contract` 只声明必须表达的语义，不声明坐标：

- `required_anchors`；
- `required_relationships`；
- `main_story_anchor_ids`；
- canvas/export 约束；
- phase、role、representation 和 style role；
- source item 与 claim 引用。

最终 Draw.io cell 必须使用精确的 `dataAnchor`：

```text
dataAnchor="visual:<anchor-id>"
dataAnchor="visual-rel:<relationship-id>"
```

## 4. 本次强化的八类问题

### 4.1 画布利用率

- 显式 landscape 画布仍为最低 `4200 x 2000`；
- 最大声明宽高比为 `2.5:1`；
- required anchor 分布按真实可见内容包围盒校验，避免被 Draw.io 的固定
  pageWidth/pageHeight 误判；
- 实际 canvas fill ratio 仍按声明画布校验。

### 4.2 过长主流程

Skill 允许在一张画布中使用连续折叠主轴，而不是强制一条极长横线。
折叠点必须保持真实连接，不能变成独立卡片岛。

### 4.3 Multimodal 细节不足

Multimodal structural region 至少需要：

- 4 个语义 anchor；
- 3 条内部 relationship；
- 输入、变换、融合或输出结构；
- eager/CUDA graph 等替代路径必须真实分叉并汇合。

### 4.4 本地编排过浅

核心方法密集的 region 必须把部分 core Method 表达为 `rendered_detail`，
不能全部聚合进一个容器。单个 anchor 最多吞并 8 个 source item。

### 4.5 Loading 退化成长总线

- Loading 必须位于 runtime 下方；
- loading 首行与 runtime 的垂直间距受限；
- loading anchors 的横向跨度受限；
- mapper/loader 应靠近真实接收组件；
- loading 不得使用 runtime tensor-flow 样式。

### 4.6 标题层级

- 页面标题和工程问题必须是两个独立可见 cell；
- region 标题必须是独立文本 cell；
- region 标题必须靠近对应可见子图；
- capability 和 legend 不能把画布无意义地撑宽。

### 4.7 Evidence `symbol` 警告

完整 Plan 2.2 中，Evidence `symbol` 无法在引用行命中时由 warning 升级为
error。Validator 支持精确 qualified symbol 和其最终 Python identifier。

### 4.8 视觉修订过浅

第一稿必须保存为 `architecture-draft1.drawio`。最终图相对 Draft 1 至少需要：

- 改变 15% 的 required anchor geometry，且不少于 4 个；
- 改变至少 2 条 required edge route；
- 真实导出并打开 PNG；
- 在 `visual-review.md` 记录发现、修改和剩余风险。

## 5. Validator 修复

`validate_architecture_plan.py` 新增：

- branch 至少两个输出；
- merge 至少两个输入；
- 重复 source/target relationship 拒绝；
- structural region 深度门槛；
- core Method detail 覆盖；
- source item 聚合上限。

`validate_drawio.py` 新增：

- title/question/region heading 的精确 cell 校验；
- region heading 与子图距离；
- local region density；
- loading gap 与 span；
- routed edge detour ratio；
- Draft 1 与 Final 的几何差异；
- required anchor 在 occupied-content envelope 中的分布；
- container/badge region 的标题定位修复。

`validate_evidence.py` 新增完整 Plan 2.2 的严格 symbol 校验。

## 6. Qwen3 VL 实验

本次使用 `samples/qwen3_vl.py` 完成真实 Draw.io MCP 重绘：

- 11 个 Class；
- 80 个 Method；
- 3 个 module function；
- 112 个 Branch；
- 5 个 Mapping Group；
- 13 个 direct Claim；
- 2 个 external Claim。

图中新增或展开：

- Processor prompt update、vision info、image/video placeholder；
- eager 与 CUDA graph 分支/汇合；
- Vision Block 的 attention boundary、residual 和 MLP；
- EVS token selection、VidCom2、MRoPE；
- first/non-first PP input 和 non-last/last PP output；
- local decoder layer loop、DeepStack injection、final RMSNorm；
- Vision、MultiModelKeys 和 Wrapper 的局部 loading mapping。

视觉结果：

- Draft 1：`12764 x 3514`，宽高比 `3.63:1`；
- Final：`7282 x 4324`，宽高比 `1.68:1`；
- 两轮实质 MCP visual review；
- 最终 Plan、Evidence 和 Draw.io Validator 全部通过。

## 8. 兼容性

v2.2 仍兼容 Plan 2.1 Golden Example。Source Context 与 Evidence Schema
没有为本次视觉收敛进行不必要升级。

生产脚本没有加入 HY V3、Qwen、Llama 或 Mixtral 的固定页面与坐标。

## 9. 当前限制

1. Visual Contract 不能替代 Agent 的源码理解能力。
2. Validator 不进行完整像素级 OCR、碰撞或美学评分，PNG 人工视觉复查仍是
   必须步骤。
3. 单画布复杂模型需要缩放浏览，Draw.io/SVG 是主要阅读载体，README PNG
   更适合作为预览。
4. imported vLLM runtime internals 在未读取相关文件时必须保持 external。
5. 本轮没有真实 vLLM checkout，因此未执行全 models 目录 scan。

## 10. 结论

v2.2 没有回到强工程、低泛化的模型模板。它把高质量 baseline 的关键特点
转化成通用验收约束：

```text
源码证据
  -> Agent 架构理解
  -> Agent 编写 Visual Contract
  -> Draw.io MCP 自主布局和修订
  -> 脚本验证锚点、关系、证据与成品质量
```

这不能保证不同模型生成完全相同的视觉风格，但能显著降低“几张简陋卡片也被
认定为完成”的概率。
