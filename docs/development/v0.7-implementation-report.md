# v0.7 Implementation Report

## 1. v0.6 图仍显简陋的原因

v0.6 已经把 Architecture IR 作为 Draw.io 的唯一语义来源，并实现了确定性 IR 到 Draw.io 渲染。但它仍只有 Model Overview 和 Decoder Layer Detail 两页，图的信息层级偏浅：Attention 内部的 QKV、RoPE、QK Norm、vLLM Attention、输出投影没有独立页面；vLLM 适配层面的配置、接口、权重加载和并行分区关系也没有单独表达。

视觉上，v0.6 的容器标题、subtitle、badge、variants 注释仍容易挤在同一块区域。普通 runtime edge 还会显示 `hidden states` 一类重复标签，Decoder Detail 的 residual edge 依赖默认正交布线，容易穿过主流程节点或压住文本。

## 2. v0.7 的目标

v0.7 的目标是保留 v0.6 的确定性流水线，同时生成四页内容层次更清楚的 Draw.io 文件：

- Model Overview
- Decoder Layer Detail
- Attention Detail
- vLLM Adaptation Map

本次没有实现 MoE Detail、Weight Mapping Detail、完整 vLLM Engine 图、通用 DAG 自动布局、更多模型适配或插件发布。

## 3. Attention Detail 建模方式

Attention Detail 页面来自 `HYV3Attention.__init__` 和 `HYV3Attention.forward` 的 source-analysis 事实。页面包含 `attention_input`、`qkv_projection`、`split_qkv`、`attention_path`、`hpc_rope_norm`、`fallback_qk_norm`、`rotary_embedding`、`attention_core`、`output_projection`、`attention_output`。

语义主线为 Hidden States 到 QKV Projection，再 Split Q/K/V。之后分成两条互斥分支：HPC fused path 走 `hpc_rope_norm`，fallback path 走 `fallback_qk_norm` 再到 `rotary_embedding`。两条路径汇合到 `attention_core`，随后到 `output_projection` 和 `attention_output`。

## 4. HPC/fallback 分支证据

HPC 分支使用 `self.hpc_rope_norm` 的赋值和 forward 中对 `self.hpc_rope_norm(...)` 的调用作为 direct evidence。Fallback 分支使用 `self.q_norm`、`self.k_norm`、`self.rotary_emb` 的赋值和 forward 调用作为 evidence。

IR 中保留完整 condition 表达式，但 Draw.io 中只显示短标签 `HPC supported` 和 `fallback`，避免把源码级 Python 条件直接放到边标签上。

## 5. vLLM Adaptation Map 的范围和边界

Adaptation Map 不是 runtime tensor-flow 图，而是 HY V3 adapter 与 vLLM API/组件的适配关系图。它分成五个区域：

- Hugging Face Inputs
- vLLM Configuration
- Adapter Interfaces
- vLLM Execution Components
- Weight and Parallel Adaptation

该页面只使用输入文件中出现的 import、继承、装饰器、模块赋值、配置访问、parallelism hint、class attribute 和 load_weights 相关事实。页面包含 SupportsPP、SupportsLoRA、MixtureOfExperts、support_torch_compile、ParallelLMHead、LogitsProcessor、FusedMoE、AutoWeightsLoader、TP/PP/EP 和 packed/stacked/expert mapping 等节点。

## 6. 为什么不能画完整 vLLM Engine

`samples/hy_v3.py` 是模型 adapter 文件，不包含 Scheduler、Worker、EngineCore、Request batching 或 Sampling 的源码事实。把这些系统组件画进去会违反 source-grounded 原则，也会让 Architecture IR 和实际输入文件脱节。因此 v0.7 明确禁止 Adaptation Map 出现这些未在文件中出现的系统组件。

## 7. 页面专用布局设计

`render_drawio.py` 新增四个页面专用布局函数：

- `_layout_overview()`
- `_layout_decoder_detail()`
- `_layout_attention_detail()`
- `_layout_adaptation_map()`

Overview 使用紧凑横向布局，把 `HYV3Model` 作为 body 容器，LM Head 和 Logits Processor 放在 `HYV3ForCausalLM` 内但位于 model body 外。Decoder Detail 使用两行主流程和 residual lane。Attention Detail 使用上下分支并在 vLLM Attention 汇合。Adaptation Map 使用五列区域。

## 8. edge label 简化规则

Architecture IR 0.4 在 `edge.display` 中增加 `show_label` 和 `route`。普通 runtime edge 默认 `show_label=false`，Draw.io 中不显示 `hidden states`、`tokens`、`input ids` 等重复标签。Residual、dependency、branch、weight mapping、parallel partition 只显示短标签。

## 9. residual waypoint 设计

Renderer 根据 `edge.display.route` 生成固定 `mxPoint`。`top_lane` 会把路线抬到节点上方，`bottom_lane` 会把路线放到节点下方。Decoder Detail 的两条 residual edge 分别使用不同 lane，以避免重叠和穿过节点正文。

## 10. Visual Validator 设计

新增 `validate_visual_layout.py`。它解析 Architecture IR 与 Draw.io XML，一次性报告所有视觉错误，包含：

- 非容器语义节点重叠；
- 装饰节点覆盖普通语义节点正文；
- 节点越出页面；
- 子节点越出父容器；
- 页面宽高比超过 2.4；
- 可见 edge label 超过 32 字符；
- runtime edge 显示标签；
- residual edge 缺少 route waypoints；
- Attention Detail 缺少两条独立分支；
- Adaptation Map 缺少五个视觉区域。

## 12. 核心函数说明

`extract_architecture.extract_architecture(source_path)` 输入 Python 文件路径，输出 source-analysis JSON。v0.7 新增 import 与 decorator 事实记录，但不改变已有 AST 抽取职责。

`build_architecture_ir.build_architecture_ir(data)` 输入 source-analysis JSON，输出 Architecture IR 0.4。核心逻辑是先识别 top-level/model/decoder/variants，再分别构造 overview、decoder detail、attention detail 和 adaptation map 四页。

`_build_attention_detail_page(data, core)` 输入 source-analysis 与核心识别结果，输出 Attention Detail page。它根据 `HYV3Attention` 的 module assignments 和 forward control flow 生成 QKV、HPC/fallback、Attention Core、Output Projection 等节点和边。

`_build_adaptation_map_page(data, core)` 输入 source-analysis 与核心识别结果，输出 Adaptation Map page。它把 import、继承、装饰器、权重映射和并行提示转换为适配关系节点和边。

`render_drawio.render_drawio(ir)` 输入 Architecture IR，输出 deterministic Draw.io XML 字符串。它逐页渲染，保证 IR node/edge 与 Draw.io semantic cell 一一对应。

`_layout_overview()`、`_layout_decoder_detail()`、`_layout_attention_detail()`、`_layout_adaptation_map()` 输入 IR page，输出固定 LayoutBox 与装饰元素。它们不推断语义，只决定坐标。

`validate_architecture_ir.validate_architecture_ir(data)` 输入 IR JSON object，输出错误列表。它校验 schema_version、page_type、node/edge 引用、phase、scope、evidence、variants、badge、edge display 等语义规则。

`validate_visual_layout.validate_visual_layout(ir, drawio_path)` 输入 IR 与 Draw.io 文件，输出视觉错误列表。它检查重叠、越界、route waypoints、edge label 和页面结构。

## 17. HY V3 实验输出分析

生成的 source-analysis 文件是 `outputs/hy-v3-v0.7-source-analysis.json`。它保留 v0.2 既有字段，并新增 imports/decorators 事实用于 vLLM Adaptation Map。

生成的 Architecture IR 文件是 `outputs/hy-v3-v0.7-architecture-ir.json`。其 schema_version 为 `0.4`，包含四个 page。Overview 没有独立 Attention 节点；Attention 细节转移到 `attention_detail`。Adaptation Map 没有 Scheduler、Worker 或 EngineCore。`unresolved` 中仍保留 `external_config_values`，因为 `config.num_hidden_layers`、`config.first_k_dense_replace` 等配置值不能从单个 Python 文件中确定。

## 18. 当前限制

- 仍只针对 HY V3 风格的常见 Transformer Overview 做固定布局。
- Attention Detail 只覆盖当前 source-analysis 能识别的 QKV、HPC/fallback、RoPE、Attention Core、Output Projection。
- Adaptation Map 是 adapter 视图，不是完整 vLLM 系统架构图。
- MoE Detail 和 Weight Mapping Detail 尚未实现。
- Visual Validator 能抓明显问题，但不能替代人工视觉审核。

## 19. v0.8 建议

v0.8 建议聚焦：

- MoE Detail 页面；
- Weight Mapping Detail 页面；
- 更完整的 checkpoint mapping 展示；
- 更通用但仍确定性的页面布局策略；
- 多模型回归样例；
- SVG foreignObject 兼容性观察与必要修复。
