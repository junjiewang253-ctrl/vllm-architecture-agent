# v1.0.1 View Architect Report

## 1. Why Concept Graph Should Not Render Directly

v1.0 introduced the Architecture Concept Layer, but the generated Draw.io file
still looked like concept cards. That proved source-grounded understanding, but
it did not answer how the adapter works. A mentor could see concepts such as
Tensor Parallel QKV Projection, but not the runtime path, Q/K/V channels, MoE
routing path, checkpoint mapping flow or local/external boundary.

v1.0.1 fixes this by adding Architecture View Graph between Concept Graph and
Renderer.

## 2. View Graph Design

Architecture View Graph schema `0.1` contains pages, nodes, edges, groups,
lanes, boundaries and legend.

View nodes are not concept nodes. They are architecture expression nodes:

- `component`: QKV Projection, FusedMoE, Logits Processor.
- `data`: Hidden States, Q Path, K Path, V Path.
- `process`: Router, RoPE Processing, Q/K Processing.
- `storage`: HF Checkpoint, KV Cache Boundary.
- `boundary`: vLLM Attention Backend, FusedMoE Runtime.
- `capability`: Tensor Parallel, Expert Parallel.

Every core node records both `concept_refs` and `fact_refs`, preserving
traceability while allowing a human-readable diagram.

## 3. Agent View Architect Workflow

`run_view_architect.py` reads:

- `architecture-concept.json`;
- `source-fact-graph.json`.

It outputs `architecture-view.json`. This phase answers: “How should a human see
the architecture?” It can choose nodes, page structure and edge types, but it
cannot modify facts or concepts.

## 5. Attention Page Design

The Attention page now shows real architecture flow:

Hidden States -> QKV Projection -> Q/K/V Split.

Q and K flow through Q/K Processing and RoPE. V flows separately into the vLLM
Attention Backend. KV Cache is represented as a boundary, not as direct local
runtime internals. The backend then crosses an external boundary to Output
Projection.

This avoids the v1.0 problem where “Tensor Parallel QKV Projection” and “KV
Cache Boundary” were just cards.

## 6. MoE Page Design

The MoE page shows:

Hidden States -> Router -> FusedMoE -> Routed Experts -> Output.

Shared Experts are shown as optional dependency into FusedMoE. Expert Parallel is
shown as a parallel capability, not as a runtime tensor input.

## 7. Checkpoint Page Design

The Checkpoint page shows mapping flow:

- HF Checkpoint -> q/k/v weights -> qkv_proj;
- gate/up weights -> gate_up_proj;
- expert weights -> expert params;
- mapped parameters -> vLLM Parameters.

This is not runtime tensor flow; edge type is `mapping`.

## 8. Validator

`validate_architecture_view.py` checks:

- every core node has concept refs and fact refs;
- pages have purpose and at least three nodes;
- pages are not concept-card-only;
- architecture edges are not all annotation edges;
- component/process nodes are connected;
- external boundary nodes do not emit ordinary runtime data flow into local
  components.

`validate_architecture_quality.py` still checks concept evidence, relationships
and boundary reports.

## 9. Renderer Changes

`layout_diagram.py` and `render_drawio.py` now normalize Architecture View Graph
into the internal renderable View structure. Renderer reads View Graph, not
Concept Graph. `apply_view_layout.py` wraps deterministic layout generation.

## 11. v1.0 Comparison

v1.0: Concept Graph -> Draw.io, resulting in concept cards.

v1.0.1: Concept Graph -> View Graph -> Draw.io, resulting in actual architecture
expression with flows, mappings, storage boundaries and parallel capability
relationships.

## 12. Current Limits

- View Architect is still conservative and HY V3-focused.
- The renderer uses deterministic layout hints, not a full general graph layout
  engine.
- External vLLM internals remain boundaries.
- Multi-model validation is still the next step.
