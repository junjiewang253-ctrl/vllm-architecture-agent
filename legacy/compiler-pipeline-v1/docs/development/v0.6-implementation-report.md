# v0.6 Implementation Report

## 1. 本次任务目标

v0.6 的目标是在 v0.5 已有的确定性 `Architecture IR -> Draw.io` 渲染基础上，生成真正有内容层次的多页面架构图。

本次只实现两个页面：

- Model Overview
- Decoder Layer Detail

流程保持：

```text
Python source
-> extract_architecture.py
-> source-analysis.json
-> build_architecture_ir.py
-> architecture-ir.json
-> validate_architecture_ir.py
-> render_drawio.py
-> drawio
-> validate_drawio.py
-> Draw.io MCP open/export
```

本次没有实现 Attention Detail、MoE Detail、Weight Mapping Detail、Parallelism 页面、通用 DAG 自动布局、第三方布局依赖或更多真实模型。

## 2. v0.5 图为什么仍然简陋

v0.5 的最大改进是确定性 Renderer 和 Draw.io Validator，但图本身仍然偏“单页概要”：

- Overview 同时放了模型级结构和 Decoder 内部 Attention，层次混在一起。
- `parent_id` 已经能表达容器关系，但单页图无法给 Decoder Layer 足够空间展示内部阶段。
- repeated block 中 variants 只是和 Attention 挤在一个容器里，语义层次不够清楚。
- 一些语义边，例如 `HYV3ForCausalLM -> HYV3Model` invocation，已经由容器嵌套表达，再画可见虚线会造成视觉噪音。
- 节点显示仍容易暴露原始 Python 表达式，不够适合作为架构图标题。

v0.6 通过多页面和 `display` 字段解决这些问题：Overview 只展示模型主链路，Decoder Detail 单独展示 decoder forward 的内部阶段。

## 3. v0.6 为什么只选择 Overview 和 Decoder Detail

本次只做两个页面，是为了控制能力边界：

- Overview 是用户进入模型结构的第一层视图。
- Decoder Layer 是 Transformer 模型最重要的重复单元，也正好承载 Attention、Norm、FFN/MoE variants 和 residual handoff。
- Attention Detail、MoE Detail、Weight Mapping Detail 需要更深入的 extractor 或更复杂的 IR 设计，容易让本轮范围膨胀。

因此 v0.6 将 Attention 和 MoE 的详细内部结构留到 v0.7 以后。

## 4. Architecture IR 0.3 的 display 设计

IR schema 从 `0.2` 升级到 `0.3`。

Node 新增可选字段 `display`：

```json
{
  "label": "N x Decoder Layers",
  "subtitle": "Pipeline-local transformer stack",
  "description": "Optional longer explanation",
  "show_badges": true
}
```

设计原则：

- `node.label` 继续保存语义名称，例如 `HYV3DecoderLayer`。
- `display.label` 是图中显示的人类可读标题。
- `display.subtitle` 是图中显示的短说明。
- `repetition`、`variants`、`evidence` 保留原始精确信息。
- Renderer 优先显示 `display.label` 和 `display.subtitle`。
- `display` 不得改变节点语义。

Edge 新增可选字段 `display`：

```json
{
  "visible": false,
  "label": "hidden states"
}
```

设计原则：

- `display.visible=false` 不删除 edge。
- Renderer 仍生成对应 semantic mxCell。
- Draw.io Validator 仍检查 edge 是否存在、source/target 是否一致。
- Renderer 使用透明样式隐藏该 edge。

## 5. 多页面 IR 设计

v0.6 builder 输出：

```json
"pages": [
  {"id": "overview", "title": "Model Overview", ...},
  {"id": "decoder_layer_detail", "title": "HYV3DecoderLayer Detail", ...}
]
```

重要约束：

- 全 IR 的 node ID 保持唯一。
- 每条 edge 的 source 和 target 必须在同一 page。
- `parent_id` 不能跨 page。
- Draw.io 中每个 IR page 对应一个 `<diagram>`。
- 每个 Draw.io page 独立校验节点、边和 parent。

## 6. Builder 如何生成 Decoder Detail

Builder 没有扩展 `extract_architecture.py`，而是使用当前 source-analysis 中已有字段：

- `module_assignments`
- `forward_control_flows`
- `conditions`
- `parallelism_hints`
- `classes`

Decoder Detail 的 scope 是：

```text
HYV3DecoderLayer.forward
```

生成的语义节点：

- `decoder_input`
- `input_layernorm`
- `self_attention`
- `attention_residual`
- `post_attention_layernorm`
- `ffn_stage`
- `dense_ffn`
- `moe_ffn`
- `ffn_residual`
- `decoder_output`

主要 evidence 来源：

- `self.input_layernorm(...)` call
- `self.self_attn(...)` call
- `self.post_attention_layernorm(...)` call
- `self.mlp(...)` call
- `HYV3DecoderLayer.__init__` 中的 Dense/MoE condition

## 7. Dense/MoE construction variants 的表达

Dense/MoE 仍然不是 runtime decision。

IR 中保留完整条件：

- `layer_idx < config.first_k_dense_replace`
- `layer_idx >= config.first_k_dense_replace`

Overview 的 repeated decoder node 保留 `variants`，但 Renderer 显示简洁说明：

```text
Layer composition
First K layers: Dense FFN
Remaining layers: MoE
```

Decoder Detail 中 `ffn_stage` 也保留 `variants`，并包含两个 construction phase 子节点：

- `dense_ffn`
- `moe_ffn`

没有生成 `conditional_true` 或 `conditional_false` runtime edge。

## 8. residual handoff 的建模依据和限制

HYV3DecoderLayer 的源码使用 RMSNorm 接口处理 hidden states 和 residual：

- `self.input_layernorm(hidden_states)`
- `self.input_layernorm(hidden_states, residual)`
- `self.post_attention_layernorm(hidden_states, residual)`

源码没有显式 `torch.add`。因此 v0.6 没有声称源码里有显式加法，而是使用 derived Add/Handoff 节点表达融合行为：

- `attention_residual`
- `ffn_residual`

这些节点：

- `kind: add`
- `display.label: Residual Handoff`
- evidence 类型为 `derived`
- evidence note 说明这是 RMSNorm 返回 hidden_states/residual 的抽象

限制：

- 这不是精确 kernel-level tensor operation 图。
- 它是为了架构图可读性而建立的 source-grounded abstraction。

## 9. Renderer 多页面实现

`render_drawio.py` 已支持遍历 IR 中所有 pages：

- 每个 IR page 生成一个 Draw.io `<diagram>`。
- `<diagram id>` 使用 IR `page.id`。
- `<diagram name>` 使用 IR `page.title`。
- 输出仍是一个 `.drawio` 文件。

Renderer 仍保持确定性：

- 不使用随机数。
- 不写当前时间。
- page、node、edge、decoration 顺序来自 IR 数组顺序。
- 同一 IR 两次渲染字节级一致。

## 10. Overview 布局规则

Overview 保持紧凑左到右布局。

结构：

```text
HYV3ForCausalLM container
├── HYV3Model container
│   ├── Input
│   ├── Token Embedding
│   ├── N x Decoder Layers
│   ├── Add Residual
│   └── Final RMSNorm
├── LM Head
└── Logits Processor
```

变化：

- `HYV3Attention` 不再作为 Overview 语义节点。
- `top_invokes_model` 仍存在于 IR 和 Draw.io XML，但 `display.visible=false`，Renderer 使用透明样式隐藏。
- repeated decoder variants 显示短文本，不显示完整 Python 条件。
- badge 保留，但不覆盖标题。

## 11. Decoder Detail 布局规则

Decoder Detail 使用两行宽屏布局。

第一行：

```text
Hidden States + Residual
-> Input RMSNorm
-> Self Attention
-> Residual Handoff
```

第二行：

```text
Post-Attention RMSNorm
-> Feed-Forward Stage
-> Residual Handoff
-> Hidden States + Residual
```

FFN Stage 是容器：

```text
Feed-Forward Stage
├── Dense FFN
└── Mixture of Experts
```

并显示 construction note：

```text
Layer construction
First K layers: Dense FFN
Remaining layers: MoE
```

## 12. 隐藏语义边的实现

当 edge 有：

```json
"display": {"visible": false}
```

Renderer 行为：

- 仍创建 mxCell。
- 保留 edge ID。
- 保留 source 和 target。
- 保留 parent。
- style 追加 `opacity=0`。
- label 输出为空字符串。

Draw.io Validator 行为：

- 仍要求该 edge 存在。
- 仍检查 source/target。
- 不把隐藏 edge 当 decorative cell。

HY V3 中隐藏的 edge：

- `top_invokes_model`

## 13. Validator 新增检查

Architecture IR Validator 新增：

- schema_version 必须是 `0.3`。
- node display 必须是合法对象。
- edge display 必须是合法对象。
- `display.visible` 必须是 boolean。
- 全 IR node ID 必须唯一。
- edge ID 必须唯一。
- `parent_id` 不能跨 page。
- edge source 和 target 必须位于同一 page。
- construction phase 节点不能使用 runtime edge。
- derived Add/Handoff 节点必须包含 derived evidence。

Draw.io Validator 新增：

- 检查所有 IR page 都存在于 Draw.io。
- 检查 page ID 和 page title。
- 每个 page 独立检查节点和边。
- 不同 page 的节点不能混在同一 mxGraphModel。
- hidden edge 仍然必须存在。
- decorative cell 只能引用本页面节点或根。

## 15. 核心函数说明

### `build_architecture_ir(data)`

输入：

- source-analysis JSON dict。

输出：

- Architecture IR 0.3 dict。

逻辑：

- 校验 source-analysis version。
- 调用 `_detect_core()` 找到顶层类、模型类、decoder 类和关键 submodule。
- 调用 `_find_dense_moe_variants()` 提取 construction variants。
- 生成 Overview page。
- 生成 Decoder Detail page。
- 收集 external config unresolved。

限制：

- 当前只支持 Overview 和 Decoder Detail。
- 当前仍针对常见 vLLM ForCausalLM + make_layers 模式。

### `_build_overview_page(data, core, variants)`

输入：

- source-analysis data。
- core detection 结果。
- Dense/MoE variants。

输出：

- Overview page dict。

逻辑：

- 生成 HYV3ForCausalLM、HYV3Model、Input、Embedding、Decoder Layers、Add Residual、Final RMSNorm、LM Head、LogitsProcessor。
- 不生成 Attention 节点。
- 设置 display 文本。
- 设置 `top_invokes_model.display.visible=false`。

限制：

- Overview 只保留高层主链路。

### `_build_decoder_detail_page(data, core, variants)`

输入：

- source-analysis data。
- core detection 结果。
- Dense/MoE variants。

输出：

- Decoder Detail page dict。

逻辑：

- 使用 decoder `forward_control_flows` 的 RMSNorm、Attention、MLP 调用生成主流程。
- 使用 module_assignments 生成 Input RMSNorm、Post-Attention RMSNorm、Self Attention、Dense FFN、MoE。
- 使用 derived evidence 生成 Residual Handoff 节点。
- 使用 construction phase 表达 Dense/MoE。

限制：

- Residual Handoff 是抽象，不是显式 torch.add。

### `validate_architecture_ir(data)`

输入：

- Architecture IR dict。

输出：

- 错误列表。

逻辑：

- 校验 version、page、node、edge、display。
- 建立全局 node/page 索引。
- 检查 parent 和 edge 不跨 page。
- 检查 construction/runtime phase 约束。
- 检查 derived handoff evidence。

限制：

- 不验证布局。

### `render_drawio(ir)`

输入：

- Architecture IR dict。

输出：

- Draw.io XML 字符串。

逻辑：

- 遍历所有 pages。
- 每页生成一个 Draw.io diagram。
- Overview 使用容器递归布局。
- Decoder Detail 使用专用两行布局。
- display 控制可见文本。
- hidden edge 使用透明样式。
- decorative cells 统一 `decorative_` 前缀。

限制：

- 不是通用 DAG 自动布局。

### `validate_drawio(ir, drawio_path)`

输入：

- Architecture IR dict。
- `.drawio` 文件路径。

输出：

- 错误列表。

逻辑：

- 解析 Draw.io XML。
- 按 diagram page 建立 cell 表。
- 校验每个 IR page 存在。
- 按 page 检查 semantic node/edge、parent、source/target、geometry、container bounds。
- 检查 decorative cell parent 不跨 page。

限制：

- 不校验视觉美学。
