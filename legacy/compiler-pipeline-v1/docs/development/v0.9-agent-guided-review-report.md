# v0.9 Agent-Guided Review Report

## 1. Why Stop Expanding AST Rules

v0.8.1 already extracts stable fact IDs, method control flow, calls,
assignments, branches, configuration accesses, parallelism facts and weight
loading flows. The remaining gap was not simply "more AST": many decisions are
architectural judgment calls. Examples include deciding whether a low-level
branch deserves its own node, whether an imported component should be shown as
an external boundary, and whether several related facts should be aggregated
into one readable page concept.

v0.9 keeps deterministic extraction and validation as the trusted boundary, and
adds constrained Agent Review only where judgment is needed.

## 2. Script and Agent Responsibilities

Deterministic scripts still own parsing, baseline IR, validation, Diagram View,
layout, Draw.io XML and visual metrics. Agent-guided steps only produce:

- `semantic-review.json`
- `architecture-ir.patch.json`
- `visual-review.json`
- `diagram-view.patch.json`

These files are validated before being applied. Agents cannot directly rewrite
final Draw.io XML, cannot promote external behavior to direct evidence, and
cannot change semantic endpoints in a visual patch.

## 3. Modes

`deterministic` mode runs the v0.8.1-style baseline pipeline and is useful for
CI and regression testing.

`reviewed` mode is the v0.9 default. It adds Semantic Review, IR Patch, reviewed
coverage, Visual Review, View Patch and Review Lock. This is the intended user
workflow.

`exploratory` mode is documented as an interface for future work. It may propose
extra local files or experimental patches, but v0.9 does not auto-apply
exploratory changes.

## 4. Semantic Review Design

`build_semantic_review.py` creates a conservative review artifact. For each
required semantic inventory fact, it checks baseline IR evidence:

- direct evidence becomes `rendered_direct`;
- derived evidence becomes `rendered_derived`;
- external evidence or external boundary facts become `documented_external`;
- remaining low-level facts become `aggregated` into an existing higher-level
  page, node or concept.

The generated review also records architecture findings. In the HY V3 run, the
single major finding resolves symbolic external configuration values that were
left in baseline `unresolved`.

## 5. IR Patch Design

`architecture-ir.patch.json` contains a base IR hash, operation list and
deferred operation list. `validate_semantic_review.py` checks fact references,
confidence, finding coverage, mass-exclusion attempts, import-only behavior
evidence and stale hashes. `apply_ir_patch.py` applies operations atomically and
adds review audit metadata to the reviewed IR.

The v0.9 HY V3 patch has one applied operation:

- `resolve_unresolved` for `external_config_values`.

No deferred IR operations were produced.

## 6. Disposition Status

Semantic Coverage is now schema `0.2` and reports a relevance by status matrix:

- `rendered_direct`
- `rendered_derived`
- `aggregated`
- `documented_external`
- `excluded`
- `unresolved`
- `orphaned`

Zero unresolved means every required fact has a disposition. It does not mean
every fact is drawn as a separate node.

## 7. Visual Review Design

`build_visual_review.py` inspects the reviewed IR, baseline Diagram View,
baseline layout metrics and baseline Draw.io. It proposes presentation-only
patches. The HY V3 review adds:

- an Attention external-boundary note for KV cache read behavior;
- an adapter execution bundle for related adaptation edges.

`validate_visual_review.py` forbids semantic operations, checks IDs and hashes,
and requires major visual findings to be patched. `apply_view_patch.py` applies
only display-level operations and records audit metadata.

## 8. Review Lock

`build_review_lock.py` records hashes for source, source-analysis, inventory,
baseline IR, semantic review, IR patch, reviewed IR, visual review, view patch
and reviewed Diagram View. `validate_review_lock.py` detects stale review inputs.

Repeated generation with the same baseline and patches produced byte-identical:

- reviewed Architecture IR;
- reviewed Diagram View;
- Layout Plan;
- Draw.io XML.

## 9. Validator Guardrails

Semantic Review Validator prevents:

- duplicate dispositions;
- missing required fact disposition;
- aggregation to nonexistent targets;
- documented external facts without symbols;
- low-confidence auto-applied patches;
- behavior patches supported only by import facts;
- deleting more than 35% of baseline semantic nodes;
- unresolved/major findings without patch or deferral.

Visual Review Validator prevents:

- semantic node/edge operations;
- hash mismatches;
- unknown node, edge or page references;
- hiding optional/external correctness labels through patch operations.

## 16. Current Boundaries

v0.9 does not recursively analyze external vLLM source. It does not prove
internals of imported `Attention`, `FusedMoE`, `AutoWeightsLoader`, Scheduler,
Worker, EngineCore or request batching. It remains HY V3-heavy and should not be
presented as full multi-model vLLM support.

## 17. v1.0 Plan
