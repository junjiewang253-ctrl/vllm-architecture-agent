# v1.2 Evidence-Grounded Agent Designer Report

## 1. Current v1.1 Diagnosis

The pre-change audit is recorded in `docs/development/v1.2-current-state-audit.md`.
The main findings were:

- architect mode still executed Python templates end-to-end;
- `run_architect_review.py` and `run_design_architect.py` did not call or wait for an Agent-authored design artifact;
- Design schema was loose enough to allow summary-like pages;
- Design-to-View was mostly a mechanical copy;
- layout relied heavily on row/column placement and stale manual route IDs;
- architect mode did not run Draw.io and visual validators as part of the default path;
- tests mostly asserted node existence, not architecture story, evidence, port or visual quality.

## 2. Why the Old Agent Was Pseudo-Agentic

The old architect command generated Concept, Design, View, layout and Draw.io in
one script path. The Agent could inspect outputs afterward, but it was not the
author of the Architecture Design Graph. v1.2 changes that contract:

- scripts prepare facts, concepts and a compact Architect Brief;
- Codex authors `architecture-design.json`;
- finalize refuses to proceed without that design file;
- deterministic template generation remains only as fallback/test scaffolding.

## 3. Two-Stage CLI

`vllm-arch prepare` now generates deterministic context:

- source analysis;
- semantic inventory;
- source fact graph;
- architecture concept graph;
- boundary report;
- architect brief;
- design template.

`vllm-arch finalize` requires an explicit Design file and runs:

- Architecture Design validation;
- Architecture View compilation;
- Architecture View validation;
- pattern layout;
- Draw.io rendering;
- Draw.io semantic validation;
- visual layout validation;
- mentor report generation.

`run --mode architect` now requires `--architecture-design`; it no longer
silently falls back to static HY V3 design.

## 4. Architect Brief

`build_architect_brief.py` creates a compact context for the Agent instead of
dumping hundreds of facts without structure. It includes model profile, candidate
pages, concept summaries, external boundaries, diagram grammar and fact clusters
for model execution, decoder, attention, MoE, TP, PP, EP, checkpoint wrapper
loader, checkpoint model loader and external boundaries.

## 5. Design Schema 1.0

`design/architecture-design.schema.json` now strictly defines:

- page `view_kind`;
- page question, purpose and primary story;
- semantic node kind, role, phase, ports and display;
- edge kind, phase, ports, display and route hint;
- groups, annotations, coverage and external boundaries.

Core objects use `additionalProperties=false`. Non-annotation nodes require
source-backed concept and fact references and ports unless they are pure strategy
or boundary markers.

## 6. Agent Design Prompt

The new prompt/rules live in:

- `references/architect-design-prompt.md`;
- `references/diagram-grammar.md`;
- `references/page-patterns.md`;
- `references/visual-quality-rubric.md`.

They instruct the Agent to design engineering diagrams, not summaries: define
page questions, main paths, branches, merges, runtime/dependency/mapping
distinctions and local/external boundaries.

## 7. View Patterns

The compiler and layout support seven page patterns:

- `pipeline`;
- `block_with_residual`;
- `branch_merge`;
- `routed_container`;
- `mapping_dispatch`;
- `strategy_matrix`;
- `boundary_map`.

These patterns prevent a return to concept-card rendering.

## 8. Design to View Compilation

`compile_architecture_view.py` replaces direct Concept rendering. It converts
Design nodes into visible nodes, maps roles such as `primary` to
`primary_flow`, turns parented components into containers, maps edge kinds to
renderer styles, preserves semantic IDs and evidence references, and emits View
1.0.

## 9. Layout and Routing

`layout_diagram.py` now dispatches by `view_kind`:

- pipeline pages use compact left-to-right main flow;
- decoder pages separate hidden and residual lanes;
- attention pages show branch/merge structure;
- MoE pages render FusedMoE as a container;
- checkpoint pages separate wrapper and model load flows;
- parallel pages use independent panels;
- boundary pages use local/boundary/external columns.

The old stale `_manual_route()` path keyed by page IDs was removed from the
active routing path.

## 10. Text Measurement

`text_measure.py` provides deterministic approximate sizing. Visual validation
also uses calibrated text-fit checks so long labels are caught without requiring
Draw.io-specific layout introspection.

## 11. Visual Validator

`validate_visual_layout.py` now supports Architecture View 1.0 and checks:

- node overlap;
- edge-node intersection;
- text overflow;
- edge crossings;
- content fill ratio;
- page aspect ratio;
- attention branch correctness.

It remains backward-compatible with older IR/View artifacts.

## 12. Visual-Only Review Patch

`apply_design_visual_patch.py` and
`schemas/architecture-design-visual-patch.schema.json` define a constrained
visual patch interface. It can adjust display text, badge visibility, preferred
size, route hints, edge label visibility, region and lane. It cannot change
semantic endpoints, phase, evidence or concept/fact references.

## 13. Legacy Migration

Legacy scripts were moved or wrapped:

- `legacy/run_design_architect.py`;
- `legacy/run_view_architect.py`;
- `scripts/run_architect_review.py` now wraps baseline concept generation;
- `scripts/run_design_architect.py` remains compatibility-only;
- `scripts/run_view_architect.py` wraps the legacy view architect.

Default v1.2 architect mode does not call the static design builder unless a
caller explicitly uses deterministic/template paths.

## 18. v1.1 to v1.2 Comparison

v1.1 still let a static script produce Design and View in one path. v1.2 makes
Design an explicit, validated Agent artifact. The renderer no longer consumes
Concepts directly, and finalize performs Draw.io and visual validation.

## 19. External Boundaries

The diagrams continue to treat imported vLLM components as boundaries:

- Attention backend internals;
- HpcRopeNorm implementation details;
- FusedMoE runtime internals;
- AutoWeightsLoader and parameter loader internals.

No external behavior is claimed as direct local implementation.

## 21. Current Limits

- The Agent Design is represented as a JSON artifact; there is not yet a
  separate remote Agent runner.
- The deterministic baseline design builder remains as a template and test
  fallback.
- Visual routing is pattern-based, not a general graph layout engine.
- External vLLM internals are not recursively analyzed.
- SVG export was not attempted in this run; PNG export succeeded for all seven
  pages after sequential MCP export retries.
