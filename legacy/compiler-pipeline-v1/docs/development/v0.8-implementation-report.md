# v0.8 Implementation Report

## 1. v0.7 四张图存在的具体问题

v0.7 已经能从 Architecture IR 确定性渲染 Draw.io，并且默认生成 Overview、Decoder Layer、Attention、vLLM Adaptation Map 四页。但图的语义表达仍然偏“方框列表”：

- Decoder 页用两个 derived 的 Residual Handoff 圆形节点表示 residual 传递。这些节点不是源码里的真实模块，虽然有助于说明 fused RMSNorm 的行为，但会让主流程看起来像被额外算子打断。
- Attention 页只有 Split Q/K/V 的文本节点，没有把 Q、K、V 三条数据通道拆成可追踪的端口和局部线。V 的旁路、KV Cache write/read 也没有成为独立通道。
- vLLM Adaptation Map 把配置、接口、执行组件、并行机制和权重加载塞到一页，产生很多跨区域长线，读者很难判断哪些是 runtime flow，哪些是 dependency、capability 或 checkpoint mapping。
- Renderer 仍以固定节点坐标和简单 top/bottom lane 为主，不理解 source_port/target_port，也无法针对 Q/K/V、residual、cache、weights 做更干净的局部路由。
- Visual Validator 只检查基础节点重叠，不能发现边穿过节点、交叉数过高、文本估算溢出、页面填充率异常等问题。

## 2. 为什么单纯换颜色无法解决

这些问题不是视觉主题问题，而是语义到图形的中间层缺失。只调整颜色、字号或节点大小，无法让 renderer 知道：

- residual 是不同于 hidden states 的数据通道；
- Q/K/V 应该连接到不同端口；
- KV Cache write/read 是 cache 数据，而不是普通 tensor flow；
- checkpoint mapping 不应该和 TP/PP/EP 并行路径混在一起；
- 某些语义边应该存在但不可见，另一些边应该局部路由。

因此 v0.8 引入 Diagram View 和 Layout Plan，把“事实是什么”和“如何展示”拆开。

## 3. Diagram View 中间层设计

新增 `build_diagram_view.py` 和 `diagram-view.schema.json`。Diagram View 的顶层字段包括 `schema_version`、`source_ir_version`、`model_name`、`pages`、`style_profile` 和 `unresolved`。

每个 page 包含：

- `regions`：页面视觉区域，例如 Adapter Integration 的 External Inputs、vLLM Configuration、Adapter Classes、Interfaces & Compilation、Execution Components。
- `lanes`：数据或概念泳道，例如 Decoder 的 hidden states 和 residual state，Attention 的 HPC fused、fallback、Q、K、V。
- `visible_nodes`：语义节点的展示文本、区域、泳道、preferred_size、ports 和 badges。
- `visible_edges`：语义边的展示样式、端口、label 可见性、route_class 和 bundle_id。
- `bundles`：允许 Q/K/V 或 weight mapping 的边共享局部 trunk，但末端仍分开。
- `layout_constraints`：目标宽高比、最小间距、最长边标签等约束。

Diagram View 不创建新模型语义，不改变 edge source/target，也不把 construction、dependency 或 weight_mapping 改成 runtime。

## 4. Architecture IR 0.5 ports 设计

`architecture-ir.schema.json` 升级到 `schema_version = 0.5`，Node 新增 `ports` 字段。每个 port 包含：

- `id`
- `label`
- `direction`: `input`、`output`、`bidirectional`
- `data_kind`: `tensor`、`config`、`weights`、`cache`、`capability`、`control`

Edge 继续支持 `source_port` 和 `target_port`，v0.8 Validator 强制检查端口存在、方向正确、data_kind 与 edge kind 兼容。这样 renderer 可以用端口 anchor 而不是粗略地从节点中心连线。

## 5. Decoder hidden/residual 双通道设计

Decoder Detail 删除了 v0.7 的 `attention_residual` 和 `ffn_residual` 语义节点。新的节点是：

- `decoder_input`
- `input_rmsnorm`
- `self_attention`
- `post_attention_rmsnorm`
- `ffn_stage`
- `dense_ffn`
- `moe_ffn`
- `decoder_output`

`input_rmsnorm` 和 `post_attention_rmsnorm` 都有 residual 输入和 updated_residual 输出端口，表达源码中 RMSNorm 同时处理 hidden states 与 residual 的 fused handoff 行为。图上将 hidden states 放在主泳道，residual state 放在下方泳道，避免半页长回路线。

## 6. Attention Q/K/V 与 KV Cache 设计

Attention Detail 新增明确的 Q/K/V 通道：

- `qkv_split` 输出 `q`、`k`、`v` 三个端口；
- `q_stream`、`k_stream`、`v_stream` 作为局部通道节点；
- `attention_core` 接收 `q`、`k`、`v` 和 `kv_cache`；
- `kv_cache` 具有 `write` 和 `read` cache port。

HPC fused lane 和 fallback lane 不串联。HPC fused processing 输出 processed Q，并向 KV Cache 写入 K/V；Attention Core 从 KV Cache 读取 cache。Fallback lane 中 Q 和 K 分别经过 Q/K RMSNorm 与 RoPE，V 直接进入 Attention Core，不进入 Q/K Norm。

## 7. MoE Detail 建模依据

新增 MoE Detail 页面，只覆盖 `HYV3MoEFused` 中 source-analysis 能支持的结构：

- Flatten Tokens
- GateLinear
- Router Logits
- FusedMoE
- Routed Experts
- Optional Shared Experts
- Expert Bias
- EPLB Metadata
- Output

图中保留 `config.num_experts`、`config.num_experts_per_tok`、`config.num_shared_experts`、`num_redundant_experts`、physical/local experts、`get_ep_group`、`FusedMoE`、`shared_mlp` 的 evidence，但显示文本保持短句。没有绘制源码中不存在的 All-to-All 细节。

## 8. Adaptation Map 拆分理由

v0.7 单页 Adaptation Map 同时承担配置、接口、执行组件、并行和权重加载，导致跨区域边过多。v0.8 拆成两页：

- vLLM Adapter Integration：回答 HY V3 通过哪些配置、类和接口接入 vLLM。
- Parallelism & Weight Loading：回答 TP/PP/EP 与 checkpoint 参数映射如何在适配层呈现。

拆分后，每页只回答一个主要问题，长线数量和概念混杂明显下降。

## 9. Adapter Integration 页面结构

Adapter Integration 使用五个区域：

- External Inputs
- vLLM Configuration
- Adapter Classes
- Interfaces & Compilation
- Execution Components

`VllmConfig` 到 `CacheConfig`、`QuantizationConfig`、`ParallelConfig / EPLBConfig` 是树状分支，不画成串行链。`SupportsPP`、`SupportsLoRA`、`MixtureOfExperts`、`support_torch_compile` 作为 capability/interface 关系，不形成假继承链。Execution Components 分成 Input、Attention、FFN/MoE 和 Output 组。

## 10. Parallelism & Weight Loading 页面结构

上半部分是三条独立并行泳道：

- Tensor Parallel → TP layers
- Pipeline Parallel → PP layer range
- Expert Parallel → EP experts

下半部分是 checkpoint weight mapping：

- HF Checkpoint → q/k/v checkpoint weights → qkv_proj
- HF Checkpoint → gate/up checkpoint weights → gate_up_proj
- HF Checkpoint → expert checkpoint weights → FusedMoE expert params
- HF Checkpoint → remaining weights → AutoWeightsLoader
- qkv_proj → PP missing filter / FP8 KV scale remap

权重边使用 `weight_mapping` 样式，TP/PP/EP 使用 `parallel_partition` 样式，两类连线不混杂。

## 11. Manhattan Router 算法

新增 `layout_diagram.py`。它使用页面专用节点布局和轻量级确定性 Manhattan router：

- 从 source port anchor 出发，到 target port anchor 结束；
- 只生成水平/垂直线段；
- 检测候选路径是否穿过非端点语义节点；
- 按 direct、上方 track、下方 track、侧向 track 的顺序尝试；
- 对 Attention Q/K/V 和 checkpoint remaining weights 增加少量手工 route override，用于消除局部交叉和穿节点；
- 所有输出坐标和 waypoints 都固定，重复运行字节级一致。

## 12. port anchor 与 track 分配

新增数据结构：

- `LayoutBox`
- `PortAnchor`
- `RoutedEdge`

默认 input port 在左侧，output port 在右侧。Attention 特殊端口使用固定 offset：`qkv_split.q/k/v`、`attention_core.q/k/v/kv_cache`、`rotary_embedding.q_in/k_in/q_out/k_out`。Residual port 走下方 lane，KV Cache 使用 cache_write/cache_read route，weight mapping 使用横向映射 track。

## 13. edge bundle 设计

Diagram View 为 Q/K/V split 边生成 `qkv_bundle`，为 checkpoint mapping 边生成 `weight_mapping_bundle`。当前 Layout Plan 允许 bundle 共享局部 trunk，但末端仍按端口分开。v0.8 没有实现通用 bundling optimizer，保留给 v0.9。

## 14. 文本尺寸估算

`build_diagram_view.py` 提供 `_measure()`，根据 label、subtitle 和 badge 数量估算 preferred size。Visual Validator 使用 `_estimated_text_fits()` 检查节点文本是否超出节点矩形。显示层不展示长 Python 条件、行号或初始化参数，精确信息保存在 IR 的 `repetition`、`variants` 和 `evidence`。

## 15. Visual Validator 新指标

`validate_visual_layout.py` 现在输出 `layout-metrics.json`，每页记录：

- node_count
- visible_edge_count
- node_overlap_count
- edge_node_intersection_count
- edge_crossing_count
- text_overflow_count
- page_aspect_ratio
- content_fill_ratio
- cross_region_edge_count

验收阈值包括：节点重叠为 0、edge-node intersection 为 0、text overflow 为 0、content_fill_ratio 在 0.25 到 0.80 之间、宽高比在 1.65 到 1.95 之间，并按 page_type 限制 edge crossing。

## 17. 核心函数输入、输出和逻辑

`build_architecture_ir.build_architecture_ir(data)`：

- 输入：source-analysis JSON object。
- 输出：Architecture IR 0.5。
- 逻辑：先复用 source-analysis 中 classes、module_assignments、forward_control_flows、parallelism_hints、weight_mappings 等事实识别核心类，再生成六页 IR。所有主要节点和边带 evidence。限制是目前仍针对 HY V3/Transformer adapter 的模式。

`build_diagram_view.build_diagram_view(ir)`：

- 输入：Architecture IR 0.5。
- 输出：Diagram View 0.1。
- 逻辑：为每页分配 regions、lanes、visible_nodes、visible_edges、bundles 和 layout constraints，继承 IR node/edge semantic_id，不改变语义。限制是 region/lane 规则仍是页面专用 preset。

`validate_diagram_view.validate_diagram_view(ir, view)`：

- 输入：Architecture IR 和 Diagram View。
- 输出：错误列表。
- 逻辑：检查每个 semantic_id 是否存在、edge source/target 是否未改变、端口是否合法、region/lane/member 引用是否合法、Adapter/Parallelism 拆页是否符合范围。

`layout_diagram.build_layout_plan(view)`：

- 输入：Diagram View。
- 输出：Layout Plan 0.1。
- 逻辑：使用页面专用 LayoutBox preset、port anchor、Manhattan route 和少量局部 override 生成确定性坐标与 waypoints。限制是还不是通用 DAG layout。

`render_drawio.render_drawio(view, layout_plan)`：

- 输入：Diagram View 和 Layout Plan。
- 输出：Draw.io XML 字符串。
- 逻辑：按 view 的 semantic nodes/edges 创建 mxCell，按 layout_plan 写 geometry、parent、sourcePort、targetPort 和 waypoints；decorative cell 使用 `decorative_` 前缀。

`validate_drawio.validate_drawio_with_view(ir, drawio_path, view, layout_plan)`：

- 输入：IR、Draw.io 文件、Diagram View、Layout Plan。
- 输出：错误列表。
- 逻辑：先检查 IR 与 Draw.io 的 node/edge 一一对应，再检查端口、visible edge waypoints 和 layout page 对齐。

`validate_visual_layout.build_layout_metrics(ir, drawio_path)`：

- 输入：IR 和 Draw.io 文件。
- 输出：metrics 列表和错误列表。
- 逻辑：解析每页 mxGraphModel，计算节点矩形、边段、交叉、edge-node intersection、文本估算、页面填充率和宽高比。

## 23. 当前限制

- Diagram View 和 Layout Plan 仍使用 HY V3/Transformer overview 的页面专用规则，不是任意 DAG 自动布局。
- Manhattan router 只有轻量避障和少量页面专用 route override，没有全局最短路或最少交叉优化。
- Adapter Integration 和 Parallelism & Weight Loading 只表达 `hy_v3.py` 中有证据的适配范围，不画完整 vLLM Engine。
- MoE Detail 没有展开源码中未显式出现的 All-to-All、调度器或 runtime batching 细节。
- Visual Validator 的文本测量是近似估算，不等同于 Draw.io 的真实字体排版引擎。

## 24. v0.9 建议

- 将 Diagram View preset 抽象为可扩展的 page template。
- 为 Manhattan router 增加更系统的 track allocator 和 edge bundle validation。
- 增加更多 vLLM model adapter 的回归样本，但仍保持 source-grounded。
- 增加更细的 Weight Mapping Detail 页面，前提是先扩展 IR 中 checkpoint mapping 的结构化表达。
- 为 Visual Validator 增加真实导出图像的像素级检查，辅助发现 Draw.io 渲染器与 XML 几何之间的差异。
